## Part 1 · One set of words

### The words

| Kind | Word on the page | Plain hint (first time on a screen) | Was also called |
|---|---|---|---|
| entity | **Entity** | a kind of thing in your business | thing, type, object |
| field | **Field** | one fact about an entity, like a column | column, property |
| link | **Link** | how two entities connect | relationship |
| metric | **Metric** | a number every agent computes the same way | number, logic |
| function | **Function** | an operation an agent can run with its own tools | operation |
| guardrail | **Guardrail** | a rule an action must not break | rule, constraint |
| action | **Action** | something agents may do | |
| source | **Source** | where an entity's rows come from | place rows come from, connection |
| binding | **Promo sale's source** (no separate noun) | which source an entity's rows come from | data binding, where rows come from |
| glossary word | **Also called** | another word people use for an entity | word, term |

Rules:
- **A word that names a kind uses this table.** "A new metric: Promo sale revenue", never "a new number".
- **Plain English about a file stays plain.** "Which number in promo_sales.csv is the result?" names a column, not a kind, so it stays.
- **Field, not column.** The exception is when the text talks about the file itself: "14 columns in the file, saved as 14 fields".
- **The sidebar's group name "Logic" stays.** It holds metrics and functions. The Logic screen's headings become "Metrics" and "Functions" (not "Numbers" and "Operations").
- **The review headline stays a sentence about intent**: "ChatGPT wants Lorefile to remember a file". The parts under it use the table.

### The hint line

One line, under the first heading that uses a kind, naming only the kinds on that screen:

```
ADDS     1 entity (Promo sale, 14 fields) · 1 metric (Promo sale revenue) · 1 source (user_files)
         Entity: a kind of thing in your business · Metric: a number every agent computes the same
         way · Source: where an entity's rows come from
```

- It is in muted text, the `hint` class, and is never a tooltip.
- A screen with no kinds (Settings, History) has none.
- Settings gets a card, "Words Lorefile uses", with the whole table. The README's word table gets the same rows.

### Where the words live

| Where | What changes |
|---|---|
| `src/ui/index.html` `KIND_WORD` | entity → "entity", metric → "metric", source → "source", rule → "guardrail", word → "also called" |
| `renderAgents` `kindWord` | Number → Metric, "Where rows come from" → "<Entity>'s source", Word → "Also called", Rule → Guardrail |
| `renderLogic` | headings "Metrics · 1" and "Functions · 0"; the intro card rewritten with the table's hints |
| `src/review.rs` `kind_noun` | thing/things → entity/entities, number → metric, "place rows come from" → source, rule → guardrail, word → "also-called word" |
| `src/review.rs` `headline` | "a new thing" → "a new entity", "a new number" → "a new metric", "a new place rows come from" → "a new source", "a new rule" → "a new guardrail" |

| activity lines (`object_words`) | follow `headline` |
| `src/mcp.rs` tool descriptions | `describe` says "one thing: an entity type…" and becomes "one item: an entity…". Everything else already says entity. |

Unchanged on purpose:
- tool names
- JSON keys (`kind: "entity"` was already right)
- `learn_file`'s questions to the user
- `trust.rs` `Kind::word` ("metric", "data binding", "word", "guardrail") and `Kind::noun` ("definition", "data binding", "word", "rule"). They feed W113 and W114 messages, refusals, and `say`, which agents repeat. Add a `Kind::name_words(name)` that gives:
  - "metric promo_sale_revenue"
  - "source of PromoSale"
  - "also-called word \"promo line\""
  - "guardrail RET-001"

  Use it wherever `kind.word()` and a name are joined (29 places). `noun` becomes "definition", "choice of source", "also-called word", "guardrail". `say` then reads "a person stands behind this choice of source".

## Part 2 · The Logic screen leads with a sentence

**Before** (branda today):

```
┌───────────────────────────────────────────────────────────────────────────────┐
│ promo_sale_revenue   transactional                 no owner yet   ● checked 27 Nov │
│ Vinay · user_files · "looked at other tables"                                  │

│ logic/metrics.yaml                          [Check again…] [Edit YAML]         │
└───────────────────────────────────────────────────────────────────────────────┘
```

**After**:

```
┌───────────────────────────────────────────────────────────────────────────────┐
│ Promo sale revenue                                          ● checked          │
│ Add up revenue, leaving out lines where refunded is true.                      │
│ Revenue from promo sale lines, refunded lines left out.                        │
│                                                                                │
│ ● Checked against user_files by a person (no name was given), 27 Nov:          │
│   "looked at other tables". Agents use it. [Put your name on it]               │
│ ! Owner: [ Vinay              ] [Save]   who decides what this metric means    │
│                                                                                │
│ ▸ Details                                                                      │
└───────────────────────────────────────────────────────────────────────────────┘
  ▾ Details
    From       user_files · promo_sales (files people give agents)
    Formula    sum(revenue) where refunded = false
    Kind       transactional: counted from records, not modelled
    Name       promo_sale_revenue · logic/metrics.yaml          [Edit YAML]
    [ Check again… ]
```

Rules:
- **Line 1 is the label** (`words::label`). The YAML name moves into Details.
- **Line 2 is the sentence** from `words::metric_sentence(m, ont)`, sent in `/api/summary` as `metrics[].sentence`. When the recipe can't be put into words (free SQL, or an expression it can't parse), the sentence is "Counted by its own recipe; see Details", and the formula shows under Details, not hidden.
- **Line 3 is the description**, if any. When it says the same as the sentence, it is still shown: it is the person's words.
- **The grade lines** are Part 3's.
- **The owner line** is Part 4's. With an owner it reads "Owner: Vinay".
- **Variants**: one sentence per variant, under the first: "When channel is affiliate: add up commission". Each variant's source goes in Details.
- **Caveats** sit in their own line above Details, "Caveat: …", because agents repeat them.
- **Details remembers open or closed** per metric for the session, so editing the owner does not fold it shut again.
- **Functions** follow the same pattern:
  - the label
  - the description as the sentence
  - "Takes X, gives Y" in words
  - "Runs: calls a tool on the shop MCP server"
  - the owner line
  - In, Out, `runs` and file under Details

## Part 3 · Accepted and checked, said plainly

The three grades already exist (`trust.yaml`). Only the way they are shown changes.

| Grade | The line on a card | What it means |
|---|---|---|
| proposed | ▲ **Unverified**: proposed by ChatGPT on 27 Nov; no person has looked. [Looks right] | agents say "unverified" before using it |
| accepted | ✓ **Accepted by Vinay, 27 Nov: agents use it.** | a person stands behind it; this is all that is needed |
| checked | ● **Checked against user_files by Vinay, 27 Nov**: "looked at other tables". Agents use it. | optional: someone compared it with real numbers |
| changed since | ✎ **Changed since Vinay accepted it on 27 Nov.** Look again. [Looks right] | edited outside Lorefile; the only time you accept again |
| ungraded | Nobody has graded this yet. [Looks right] | hand-written and never vouched for |

- **A checked item shows one line, and it ends "Agents use it."** `trust.yaml` keeps one record per item, and a check replaces the accept's record, so who accepted it is not kept once it is checked. A check is only allowed after an accept (`edit.rs` refuses one on an ungraded item: "accepts it first"), so "agents use it" is always true of a checked item.
- **The check is a quiet link** under an accepted item: "I compared it with real numbers… (optional)". It opens the same sheet as today (`openCheck`). The sheet's title changes to "You compared Promo sale revenue with real numbers". When checked, the link reads "Check again…".
- **There is no "accept again"** except after "changed since". An accepted item never shows Looks right, as today.
- **A "What do these mean?" toggle** sits under the first grade line on Logic, Entities › Data and Agents › In use. It shows three lines:
  - Accepted: a person stands behind it, and agents use it as settled.
  - Checked (optional): someone ran it against real rows and the result was right.
  - Unverified: an agent wrote it and no person has looked; agents say so.
- **Agents' words stay.** `say` already reads "Accepted by Vinay on 27 Nov: a person stands behind this definition; nobody has recorded checking it against data." That is right and unchanged.

## Part 4 · Names, and the owner

### Your name on decisions

**Before**: the review screen shows an optional "Your name" box and an "Accept as you" button. Left empty, the page sends no `by`. The server records "person via page", and every screen says "a person".

**After**:

```
Your name   [                    ]   kept in this browser, recorded with every decision
            [ Type your name to accept ]  (disabled)   [ Not now ]
                        ↓ types "Vinay"
            [ Accept as Vinay ]                         [ Not now ]
```

- **Every page decision waits for a name**: Accept, Not now (the Set aside button in its why box), Take it back, Look again, Looks right, the check sheet and Vouch for all. The button is disabled, its label says why, and the name box is focused.
- **The name rule is the server's** (`nameOk` = `by_words`): up to 60 letters, digits, spaces and `. - ' _`, with no "agent" and no "via". A refused name says why, inline.
- **Kept where it is kept today** (`localStorage` `lorefile-name`), and editable in Settings › Your name. Where the browser keeps no storage (a private window that refuses it), the name is kept in memory for the tab and still sent.
- **The server does not change.** Scripts, tests and an older page can still send no name, and the record says "person via page". The rule is the page's.
- **With `--no-auth`** the existing hint stays: anyone who can reach the server can type any name.

### On the sign-in page

`LOGIN_HTML` gets a second, optional field:

```
Lorefile
Sign in with the token printed when the server started.
Token      [ ••••••••••••••••• ]
Your name  [ Vinay             ]   optional · shown on what you accept
                                                              [ Go ]
```

- On submit, the login script saves the name to `localStorage` `lorefile-name` (same origin, so the page reads it), then posts the token as today. The name never goes to the server with the token.
- If the field is empty and a name is already kept, the field is prefilled with it.
- The name is checked with the same rule in the login script. A bad name is not saved, and sign-in still goes ahead.

### Decisions made without a name

- The review screen's state line reads **"✓ Accepted by a person (no name was given), 27 Nov"**. Grade lines say the same.
- Beside each such line: **[Put your name on it]**. It needs a name (above) and edit mode.

```
✓ Accepted by a person (no name was given), 27 Nov     [Put your name on it]
                        ↓ Vinay presses it
✓ Accepted by Vinay, 27 Nov
  activity: "Vinay put their name on ChatGPT's promo_sales.csv file (accepted 27 Nov with no name)"
```

What it changes:
- **On the review screen**, it signs the proposal and every anonymous `trust.yaml` record for the items that proposal graded. For p-6, those are the `PromoSale` binding and `promo_sale_revenue`, even though the metric has been checked since.
- **On a grade line** (Logic, Entities › Data, Agents › In use), it signs that one record.

The rules, all on the server:
- **Only anonymous records**: `by` is `person via <channel>`. A named record is refused: "already recorded as Priya's; it can't be renamed".
- **It keeps everything else**: the grade, `at`, `against`, `note` and `of`. Only `by` becomes "<name> via page".
- **The activity log says so**, in words, with the original date, so it never reads as a fresh decision.
- **With history on**, it is one commit: "Vinay put their name on …".
- **A proposal**: `accepted_by` (or `decided_by` for a set-aside) changes only when it was `person via …`.
- **Read-only servers and shipped examples** show the anonymous line without the button.

### The owner, harder to miss

On the review screen, W109's question is prefilled:

```
? Owner of Promo sale revenue: who decides what this metric means
  [ Vinay                 ]   prefilled with your name · clear it to leave it for later
```

- It is prefilled only when the metric has no owner **and** a name is known. Otherwise it stays empty, as today.
- **Accept sends it as a fix** (`set_metric` owner), as today when typed. A cleared box sends nothing.
- On the Logic card, a metric with no owner shows the inline owner box (Part 2). Save sends `{op: "set_metric", metric, owner}` to `/api/patch`. It needs edit mode, like every page edit; read-only shows "Owner: no one named yet".
- **What happens to the grade.** The fingerprint (`trust::things`) covers the whole metric, owner included. So a person's `set_metric` goes through `restamp`:
  - **Checked** stays checked, with the same who, when, against and note, and a fresh `of`, because `recipe` (what a check depends on) leaves the owner out. That is branda's case.
  - **Accepted** is accepted again by the person who set the owner, dated today.
  - **Proposed** (unverified) becomes accepted by that person: setting the owner counts as looking at it.
  - **Changed since** becomes accepted by that person too.

  For the last two, the box reads "Owner: [ ] Save · saving also accepts this metric as it is now", so nobody accepts by accident.
- **An owner typed into the YAML by hand** is a change behind the grade's back (W113), as any hand edit is.
- **"What to do next" gains the nudge it lacks.** Today the list has one for guardrails with no sign-off (`f.noOwner`) but none for metrics. So branda's "What to do next" says "Nothing waiting" while the sidebar says "1 with no owner".
  - The new nudge: "1 metric has no owner" with the metric names, and [Name an owner] → Logic, focused on the first owner box.
  - It goes away on the next summary once the owner is set, as the sidebar's count does.

## Part 5 · Counts and the picker

### The picker refreshes

- `loadSummary()` fetches `/api/spaces` and calls `renderSpacePicker()` after the summary. Every path that already calls `loadSummary` is covered:
  - Accept, Not now, Take it back, Look again
  - patches and edits
  - History › Undo
  - Reload
- **On return**: on `visibilitychange` to visible, the page calls `loadSummary()` then `render()`, but only when all of these hold:
  - no `<input>` or `<textarea>` has focus
  - no editor is open (`ui.editor`)
  - no check sheet is open (`ui.check`)
  - the last load was more than 5 s ago

  An agent's write in another tab then shows on return.
- A failed `/api/spaces` keeps the old picker. It never blanks it.

### What the picker says

| Space | Today | After |
|---|---|---|
| blank (E000 only) | `branda · 0 entities · has errors` | `branda · empty` |
| one entity, fine | `branda · 1 entities` | `branda · 1 entity` |
| warnings only | `branda · 1 entities` | `branda · 1 entity` (warnings aren't errors) |
| real errors | `x · 3 entities · has errors` | `x · 3 entities · 2 errors` |

`stats_json` adds `empty: true` when E000 is the only error. The page uses it.

### Every count

| Where | Today | After |
|---|---|---|
| header | `1 entities · 0 links · 0 guardrails · 0 actions` | `1 entity · no links · no guardrails · no actions` |
| nav Sources | `1 connected · 0 entities without data` | `1 source · every entity has data` (or `2 entities without data`) |
| nav Entities | `1 · 0 need plain words` | `1 · every field described` (or `3 need plain words`) |
| nav Links | `0 · 0 without a sentence` | `none yet` (or `4 · 1 without a sentence`) |
| nav Guardrails | `0 · 0 with no sign-off` | `none yet` (or `5 · 2 with no sign-off`) |
| nudges | `${n} entities have fields…`, `${n} links have…`, `${n} guardrails have…` | `plural()` each |
| map card | `14 fields · 0 links · 0 guardrails` | `14 fields · no links · no guardrails` |
| no-space footer | `1 space(s) of yours` | `1 space of yours` |

- **"Connected" goes.** A declared BigQuery source isn't connected to anything here, and a `from_user` source never is.
- **The readiness meter stays**, but its words change from "100% ready for agents" to "100% filled in". Its tooltip and the "What to do next" heading say what it counts: fields described, links explained, entities with data. The list carries what is left beyond that, W109 included. 100% then claims only what the meter measures.

## What this does not do

- No server-side requirement for a name: the page asks; the server still accepts a missing one.
- No renaming of named records: "Put your name on it" only fills in a missing name.
- No change to tool names, JSON keys or the YAML.
- No polling: the home page spec adds it for the home screen only.
- No dark theme.

## Edge cases

| Case | What happens |
|---|---|
| A name with "agent" or "via" in it | Refused inline with the rule; the decision waits. |
| Storage refused (private window) | The name lives in memory for the tab; it is asked again in a new tab. |
| Two people, one browser | Settings › Your name changes it. The review screen's box shows the kept name with a "not you?" link that clears it. |
| A metric with an owner and a W109-free space | No owner box; "Owner: Vinay". |
| An owner like `growth@lumenhome` | Shown as `owner()` does today ("Growth team"); the box holds the raw value when edited. |
| A metric whose recipe can't be put into words | "Counted by its own recipe; see Details"; the formula is shown under Details. |
| A shipped example | No owner box, no name requirement (nothing can be decided); grade lines still shown. |
| A read-only server | No owner box, no buttons; grade lines and the hint line still shown. |
| The tab returns while a sheet or editor is open | No refresh until it closes. |
| `/api/spaces` fails on refresh | The old picker stays. |
| A space removed on disk while open | The next refresh shows the "no space called x" banner, as `boot()` does today. |
| Changed since, then the owner is set from the page | It becomes accepted by the person who saved: `restamp` treats any person's save through Lorefile as looking at it. The owner box warns first (Part 4). |
| "Put your name on it" on a record that is "changed since" | Refused: "changed since it was accepted; look again instead". A name goes on the version a person saw, not the new one. |
| "Put your name on it" twice, from two browsers at once | The second finds a named record and is refused (the trust lock serialises them). |
| An anonymous record written by an agent's channel (`agent via MCP`) | Never offered: only `person via …` counts as anonymous. |
| A proposal accepted with no name, some of whose records were already named from the Logic card | The review screen's button signs whatever is still anonymous and says "already named" for the rest. |
| A blank space with a broken manifest too | "2 errors", not "empty": E000 must be the only error. |

## What changed during the build

Built on `claude/learn-file-6a954e` on top of `8f8ba8e`. All 18 decisions as recommended. Where the build differs from the text above:

1. **What setting an owner does to a grade, as this spec now says** (corrected while it was being built). The fingerprint covers the whole metric; `recipe`, what a check depends on, leaves the owner out. So `restamp` keeps a check, with the same who, when, source and note. It accepts an accepted, unverified or changed-since metric again in the name of whoever set the owner. For the last two, the owner box on the Logic card and on Home's card says "saving also accepts this metric as it is now". (An earlier draft of this build kept an accepted record unchanged and left changed-since alone. That was reverted to match this spec.)
2. **A bug found on the way: `set_metric` refused the page's own name.** The page sends `by` with every write, and `set_metric` refused any key it did not know, so the Logic card's owner Save (and any page `set_metric`) failed with "set_metric takes owner, description, …, not `by`" whenever a name was kept. It now ignores `by`.
3. **"Put your name on it" keeps Take it back possible.** Signing changes `trust.yaml`; a proposal whose snapshot held the text Accept wrote now holds the signed text, so a name alone never blocks Take it back. p-6's case (a check was given since) stays refused for the same reason as before.
4. **Where the name box appears.** The review screen always shows it when there is a decision to make, prefilled, with "not you?". Logic, Agents, an entity's Data tab and a guardrail show it at the top only while no name is known. Vouch for all under "What to do next" has no box beside it, so it asks once in a small prompt.
5. **"Check again…"** sits under Details on a metric card. On other screens (an entity's source, a guardrail) it is a quiet link at the end of the checked line.
6. **The hint line** is on the review screen, Logic and Agents › In use. Entities, Links, Sources, Guardrails and Actions name one kind each in their heading and the sidebar already says it, so they have none. Settings has the whole table ("Words Lorefile uses").
7. **Functions** show "Owner: …" as text. There is no op to set a function's owner, so there is no box.
8. **Variants**: `/api/summary` sends `sentences`, one per variant ("When channel is affiliate: add up commission"); `sentence` is the first. A recipe with any part shown "as written" gives no sentence, and the card says "Counted by its own recipe; see Details".
9. **The test of `review::headline`** checks the counts line instead: a learned file's headline stays "… wants Lorefile to remember a file" (Decision 1's rule), so it never named entity, metric or source either way.
10. **Left as they were**: `Kind::word` ("data binding", "word") and the summary's agent-facing "Trust (metrics, data bindings, glossary words and guardrails)" line and `[data binding UNVERIFIED]` markers. `name_words` replaced the joins of kind and name (28 places), and `noun` now says "choice of source", "also-called word" and "guardrail", so W113, W114, refusals and `say` read "source of PromoSale".
11. **The readiness meter** reads "100% filled in", with a tooltip saying what it counts. "What to do next" has the metric-owner nudge, and its heading's tooltip says what the list covers beyond the meter.
